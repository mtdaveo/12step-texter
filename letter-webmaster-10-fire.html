12th Step Texter

Introduction for Area 40 Webmaster

The 12th Step Texter is a suggestion for a more automated, streamlined system of communications between A.A. and its volunteers and the professional community, geared toward facilities potentially serving alcoholics.

How It Works Now — District 11

Currently in District 11, facility staff call or text the A.A. Coordinator's dedicated phone number with patient information. The coordinator then relays that request to the volunteer group text. Each relay step adds time — requests that should take seconds can take minutes or hours. 12th Step Texter eliminates the relay entirely. See the full Current vs. Proposed comparison →

What This App Does

It's a simple web form that lives on a phone. Here's the flow:

  1. A QR code is posted at the nurses' station (or sent to the facility contact)
  2. Staff scans it — a clean, simple form opens on their phone
  3. They fill in: facility name, room number, patient name, age, any notes
  4. They select Male or Female (routes to the correct volunteer list)
  5. They check a box confirming the patient personally requested A.A. contact — required, can't be bypassed
  6. They hit Send — their phone opens a pre-written group text to all current A.A. volunteers with all patient info filled in automatically
  7. They hit Send one more time — done

See It Live

A.A. Side
  1. Select District 11 / Billings from the Location dropdowns.
  2. Set up A.A. volunteers (phone numbers, names if you want). One list for males, another for females.
  3. Hit Save Configuration — config saves to Firebase instantly.
  4. Hit Generate QR Code — the QR points to a permanent Billings URL. Options for QR code/URL sharing:
    1. Copy URL - copy Facility form link for pasting into browser
    2. Copy QR - for sharing/showing Facility form QR code
    3. Share QR - opens device mechanism to send Facility form QR code
    4. Download QR - save Facility form QR code to device
    5. Print sheet - provides printout for Facility with instructions, QR code embedded
Facility Side
  1. On your mobile phone, scan the QR code generated above.
  2. Fill out the form for a sample patient.
  3. Hit Send Request to A.A. Volunteers.

How the Backend Works Now

The app currently uses Firebase Firestore (Google's cloud database, free tier) as its config store. The coordinator saves volunteer lists and settings to Firestore, keyed by city (e.g. billings). The facility form fetches the current config on every load. The QR code contains only a permanent city URL — it never needs to change.

Coordinator saves → Firestore: configs/billings → live immediately
Facility scans QR → loads ?city=billings → fetches from Firestore → always current

Where Area 40 Hosting Could Help

The current setup is fully functional and backed by Firebase — no server-side logic is required from Area 40. The Firebase backend handles all live config storage and will remain unchanged regardless of where the HTML files are hosted.

For a broader Area 40-wide rollout, hosting the HTML files under the aa-montana.org domain would add credibility and remove dependence on a personal GitHub account. The facility and coordinator URLs would look like:

FACIILITY FORM aa-montana.org/12step-texter/sms-facility-form-v13-fire.html?city=billings

COORDINATOR FORM aa-montana.org/12step-texter/sms-coordinator-setup-v27-fire-hc.html

Clean vanity URLs (e.g. aa-montana.org/12step/billings) would require server-side routing — a separate conversation if that's of interest. For now, simply hosting the HTML files as-is would be sufficient. The only thing that would move is where the files are served from.
